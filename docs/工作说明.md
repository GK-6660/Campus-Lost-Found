# 工作说明

每人只改自己名下的文件。字段以《软件设计说明书》为准。别人的函数还是空的时，用说明书里的假数据测自己这一段。

组长才改这四个共用文件：`backend/app/schemas.py`、`backend/app/errors.py`、`backend/app/main.py`、`frontend/src/api/types.ts`。

后端测试都在 `backend/tests/`。写成之后执行 `uv run pytest`，并和功能一起上传。前端页面在自己电脑的浏览器里点，不上传测试文件。

---

## A1 登录和请求入口

同学打开网站后要知道自己有没有登录。全组发请求都走这里，密码不能留在浏览器里。

| 代码 | 位置 |
| --- | --- |
| 请求入口 `request` | `frontend/src/api/client.ts` |
| 登录、当前用户 | `frontend/src/api/auth.ts` |

**测试：** 在浏览器里测。用一份假的用户数据假装登录成功，页面知道当前是谁。再假装未登录，页面去登录。密码不能出现在浏览器保存的数据里。请求要带上登录状态。

---

## A2 通知铃铛

有新候选时，铃铛显示未读数。点开能看到去哪一栋、为什么像，以及东西可能已经不在。

| 代码 | 位置 |
| --- | --- |
| 通知列表 | `frontend/src/api/notifications.ts` |

**测试：** 在浏览器里测。假数据里未读数是 1，正文有楼名和理由，铃铛显示 1，点开能看到那句话。未读数是 0 时，不显示新消息。请求用 A1 的入口。

---

## B1 失物登记

失主填写类别、颜色、时间、按顺序去过的楼，保存草稿并发布。

| 代码 | 位置 |
| --- | --- |
| 创建、修改、发布、确认标签 | `frontend/src/api/items.ts` |

**测试：** 在浏览器里测。字段填全，能保存并发布。漏掉时间或楼，页面指出缺什么，不能发布。不用等真的匹配结果。

---

## B2 拍照、涂黑、上传

拾到者在浏览器里涂黑后再上传，只交涂过的那一张。然后每 2 秒看一次识别进度。失败了仍能手填类别和颜色。

| 代码 | 位置 |
| --- | --- |
| 涂黑并导出 | `frontend/src/features/redact.ts` |
| 上传 | `frontend/src/api/files.ts` |
| 识别进度 | `frontend/src/api/jobs.ts` |

**测试：** 在浏览器里测，不需要后端。用一张写了姓名的照片，涂黑后把导出的图放大：姓名被挡住，黑块没有偏掉，原图不在要上传的内容里。进度先是处理中，再变成失败。失败后仍能手填。创建和发布用 B1 的函数，那个文件不要改。

---

## C 候选和已找回

失主看到最多 5 条候选和理由，并点已找回或没找到。文案是「匹配分 72/100，仅用于排序」。

| 代码 | 位置 |
| --- | --- |
| 候选 | `frontend/src/api/matches.ts` |
| 已找回、没找到 | `frontend/src/api/claims.ts` |

**测试：** 在浏览器里测。假数据有 5 条候选，每条都有理由。再试空列表，页面显示没有候选，不是报错。点已找回或没找到时，发出去的内容里有失物、拾获和结果。

管理员看待处理举报并下架。普通用户看不到这个操作。

| 代码 | 位置 |
| --- | --- |
| 举报列表和下架 | `frontend/src/api/admin.ts` |

## E1 账号和重复提交

注册、登录、退出，以及同一个提交编号不会写出两条。密码只存哈希。登录状态放在 Cookie 里。

| 代码 | 位置 |
| --- | --- |
| 注册、登录、退出、当前用户 | `backend/app/auth.py` |
| 登录相关路由 | `backend/app/api/auth.py`、`backend/app/api/deps.py` |
| 提交编号去重 | `backend/app/idempotency.py` |
| 测试 | `backend/tests/test_auth.py` |

**测试：** 把 `test_auth.py` 写成真测试并上传。同一个提交编号注册两次，只有一个用户。密码错误时登录失败，且不说明是哪一项错。返回里没有密码。没登录去下架，被拒绝。在 `backend` 目录执行 `uv run pytest tests/test_auth.py`。

---

## E2 物品和图片

保存失物和拾获，只存涂黑图，用版本号避免互相覆盖。物品状态只在这里改。

| 代码 | 位置 |
| --- | --- |
| 草稿、发布、撤回、状态 | `backend/app/items.py` |
| 物品路由 | `backend/app/api/items.py` |
| 图片 | `backend/app/files.py`、`backend/app/api/files.py` |
| 类别和颜色标签 | `backend/app/tags.py` |
| 测试 | `backend/tests/test_items.py`、`backend/tests/test_files.py` |

**测试：** 把上面两个测试文件写成真测试并上传。失物发布时没有楼，接口拒绝。用旧版本号修改，接口要求刷新。上传的不是图片，接口拒绝。别人不能读到这张图。先不测匹配对不对。执行 `uv run pytest tests/test_items.py tests/test_files.py`。

---

## F 打分和站内信

按类别、颜色、楼、时间、品牌和描述打分，并写出理由。达到条件才发一条站内信，同一对不重复。

| 代码 | 位置 |
| --- | --- |
| 打分 | `backend/app/scoring.py` |
| 候选 | `backend/app/match.py`、`backend/app/api/matches.py` |
| 站内信 | `backend/app/notify.py`、`backend/app/api/notifications.py` |
| 测试 | `backend/tests/test_scoring.py`、`backend/tests/test_notify.py` |

**测试：** 把两个测试文件写成真测试并上传。不必等网页。类别相同要有类别分和一句理由。相差不少于 7 天，时间分是 0。同一对通知两次，仍然只有一条。公式见《软件设计说明书》第 5.7 节。执行 `uv run pytest tests/test_scoring.py tests/test_notify.py`。

---

## G 识别、已找回、下架

从涂黑图读出类别和颜色。没有密钥或失败时允许手填。处理已找回，并执行下架。不自己改物品状态，要调用 E2 的函数。

| 代码 | 位置 |
| --- | --- |
| 识别 | `backend/app/extract.py`、`backend/app/api/jobs.py` |
| 已找回、没找到 | `backend/app/claims.py`、`backend/app/api/claims.py` |
| 举报和下架 | `backend/app/reports.py`、`backend/app/api/reports.py` |
| 测试 | `backend/tests/test_extract.py`、`backend/tests/test_claims.py`、`backend/tests/test_reports.py` |

**测试：** 把三个测试文件写成真测试并上传。没有模型密钥时，识别任务直接失败，不阻止手填。两个人同时对同一条拾获点已找回，只有一个成功。普通用户下架被拒绝。执行 `uv run pytest tests/test_extract.py tests/test_claims.py tests/test_reports.py`。
