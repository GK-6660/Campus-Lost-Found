# 接口字段表

**状态：** 第一周冻结稿。业务代码按本表写。  
**改法：** 先改本文件并让组长合并，再改前后端。字段名以这里的英文为准。  
**对齐：** 实现以 `软件设计说明书.md` 为准。本文保留作字段速查。若与说明书不一致，以说明书为准。

现在不写页面和接口实现。各组先按第 4 节认自己的路径。

## 1. 通用约定

| 项 | 定稿 |
| --- | --- |
| 前缀 | `/api/v1` |
| 鉴权 | HTTP-only Cookie，名 `clf_session`。前端请求带 `credentials: "include"`。不把令牌放进 localStorage |
| 数据格式 | JSON，`Content-Type: application/json`。上传图片除外 |
| 时间 | 日期 `YYYY-MM-DD`。时刻用 UTC，如 `2026-09-29T10:00:00Z` |
| 标识 | 字符串 UUID |
| 写操作 | 都带 `request_id`（客户端生成的 UUID）。同一用户的同一个 `request_id` 再提交一次，返回第一次的结果，状态码仍是当时的成功码 |
| 更新 | 带 `version`。与库中不一致时返回 `409`，前端刷新后再提交 |
| 空值 | 请求可以不传可选字段。响应里可选字段用 `null`，不省略键 |
| 角色 | 只看服务端会话。请求体里的 `role` 一律忽略 |

错误体：

```json
{
  "error": {
    "code": "version_conflict",
    "message": "物品已被更新，请刷新",
    "current_version": 4
  }
}
```

| HTTP | `error.code` | 何时 |
| --- | --- | --- |
| 401 | `unauthenticated` | 未登录 |
| 403 | `forbidden` | 登录了但不是主人或管理员 |
| 404 | `not_found` | 没有这条记录，或当前用户不该知道它存在 |
| 409 | `version_conflict` | `version` 过期。带 `current_version` |
| 409 | `found_already_returned` | 这条拾获已经被人标记已找回 |
| 409 | `invalid_state` | 当前状态不允许这个操作 |
| 422 | `validation_error` | 字段不合法。另给 `fields: [{ "name": "color", "code": "unknown_enum" }]` |

`fields[].code`：`required`、`unknown_enum`、`too_long`、`invalid_file`。

## 2. 枚举

代码用左列，界面用右列。未知值用 `unknown`，不要自造字符串。

### 2.3 地点

| 值 | 界面 |
| --- | --- |
| `library` | 图书馆 |

### 2.4 其余

| 字段 | 值 |
| --- | --- |
| `day_part` | `morning` 上午，`afternoon` 下午，`evening` 晚上 |
| `type` | `lost` 失物，`found` 拾获 |
| `status` | `draft` 草稿，`open` 开放，`returned` 已找回，`closed` 停止 |
| `role` | `user`，`admin` |
| 标签 `source` | `user`，`model` |
| `job.status` | `processing`，`succeeded`，`failed` |
| `claim.result` | `returned` 已找回，`not_found` 没找到 |
| 通知 `type` | `new_match`，`found_returned`，`item_taken_down` |

`draft` 只在发布前存在。失主点已找回后，对应失物和拾获都变成 `returned`。撤回或管理员下架变成 `closed`。没有 `reserved`。

## 3. 资源字段

### 3.1 用户 `User`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | |

`Tag`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | string | 只有 `category` 或 `color` |
| `value` | string | 对应枚举 |
| `source` | string | `user` 或 `model` |
| `confirmed` | boolean | 用户确认后才参与打分 |

候选卡上的对方物品只用公开投影，不使用上面整份 `Item`：

| 字段 | 说明 |
| --- | --- |

| `place_note` | 没有则 `null` |

| `day_part` | |
| `image_id` | 没有则 `null`。用 `GET /files/{id}` 取图 |

### 3.4 候选 `Match`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | |
| `lost_item_id` | string | |
| `found_item_id` | string | |
| `score` | number | 整数，排序用 |
| `score_max` | number | 固定 `100` |
| `notify` | boolean | 是否已写或应写站内信 |
| `reasons` | object[] | `{ "code", "points", "text" }` |
| `conflicts` | object[] | 没有则 `[]`。硬冲突如 `{ "code": "category", "text": "类别不同" }` |
| `counterpart` | object | 上一节的公开投影 |

`reasons[].code`：`category`、`color`、`place`、`time`、`brand`、`keyword`。

界面文案用「匹配分 72/100，仅用于排序」。不要写「匹配度 72%」。

展示：`score >= 40` 才出现，最多 5 条。站内信：`score >= 60`，且类别不是硬冲突，且失物 `subscribe_matches` 为 `true`。同一失物和同一拾获只通知一次。

### 3.5 找回记录 `Claim`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | |
| `lost_item_id` | string | 必须是当前用户的失物 |
| `found_item_id` | string | |
| `result` | string | `returned` 或 `not_found` |
| `created_at` | string | |

`returned`：两条物品都变为 `returned`，其他人这条拾获上的候选关掉，并给那些人一条 `found_returned`。同一拾获只能有一条 `returned`。  
`not_found`：两条都保持 `open`。以后新的拾获仍会再比、再通知。

| `type` | string | |

| `found_item_id` | string \| null | |
| `title` | string | |
| `body` | string | 写清去哪一栋、为什么像，并说明东西可能已经不在 |
| `created_at` | string | |

### 3.7 识别任务 `Job`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | |
| `item_id` | string | |
| `status` | string | |

## 4. 接口

未登录访问第 4.2 节及以后，返回 `401`。

### 4.1 账号（E）

#### `POST /auth/register`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `student_no` | 是 | |
| `nickname` | 是 | |
| `password` | 是 | |
| `request_id` | 是 | |

响应 `201`：`User`。同时写下 `clf_session`。学号重复返回 `422`，`fields[].name` 为 `student_no`。

#### `POST /auth/login`

| 字段 | 必填 |
| --- | --- |
| `student_no` | 是 |
| `password` | 是 |
| `request_id` | 是 |

响应 `200`：`User`，并写下 Cookie。学号或密码不对返回 `401`，不说明是哪一个错。

#### `POST /auth/logout`

无请求体。响应 `204`。清掉 Cookie。

#### `GET /auth/me`

响应 `200`：`User`。A 组用它恢复登录态。

### 4.2 图片（E）

#### `POST /files`

`multipart/form-data`。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 涂黑后的图片 |
| `request_id` | 是 | |

响应 `201`：`File`。类型或大小不对返回 `422`，`code` 为 `invalid_file`。

#### `GET /files/{id}`

响应是图片字节，不是 JSON。`Content-Type` 为保存时的 MIME。

可以看的人：上传者、在自己的候选里看到这张图的失主、管理员。其他人 `404`。

### 4.3 物品（E）

#### `POST /items`

创建草稿，不打分、不发通知。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `type` | 是 | `lost` 或 `found` |
| `request_id` | 是 | |
| `category` | 否 | |
| `color` | 否 | |
| `brand` | 否 | |
| `description` | 否 | |
| `occurred_on` | 否 | 发布前要补上 |
| `day_part` | 否 | |
| `visited_places` | 失物发布前必填 | 拾获不要传 |
| `places_ordered` | 否 | 失物默认 `true` |
| `found_place` | 拾获发布前必填 | 失物不要传 |
| `place_note` | 否 | 仅拾获 |
| `subscribe_matches` | 否 | 仅失物，默认 `true` |
| `image_id` | 否 | 必须是当前用户刚上传的文件 |

响应 `201`：主人视图 `Item`。手填的类别和颜色写成 `source=user`、`confirmed=true`。

#### `PATCH /items/{id}`

只有主人。草稿，或拾获标签还没确认时，可以改类别、颜色、品牌、描述、地点、日期、时段、`place_note`、`subscribe_matches`。已经 `open` 且标签已确认之后，只能改 `subscribe_matches`。

| 字段 | 必填 |
| --- | --- |
| `version` | 是 |
| `request_id` | 是 |
| `confirm_tags` | 否 | `true` 时把现有类别、颜色标成用户已确认，并触发匹配 |

其余字段与创建时相同，都可选。至少还要改一个字段。

响应 `200`：更新后的 `Item`。

#### `POST /items/{id}/publish`

| 字段 | 必填 |
| --- | --- |
| `version` | 是 |
| `request_id` | 是 |

失物发布条件：`occurred_on`、`day_part`、`visited_places` 至少 1 个。  
拾获发布条件：`occurred_on`、`day_part`、`found_place`。

发布后 `status=open`。

- 失物：立刻和现有 `open` 拾获打分。
- 拾获且类别颜色都已确认：立刻和现有 `open` 失物打分。
- 拾获有图但类别或颜色还空着：创建 `job`，`status=processing`。匹配等用户确认标签后再做。

响应 `200`：`Item`（含 `job_id`）。

#### `POST /items/{id}/close`

主人撤回。`open` 才能关。

| 字段 | 必填 |
| --- | --- |
| `version` | 是 |
| `request_id` | 是 |

响应 `200`：`Item`，`status=closed`。之后不再匹配、不再通知。

#### `GET /items`

只返回当前用户的物品。可选查询：`type`、`status`。一次最多 100 条，按 `updated_at` 倒序。

响应 `200`：

```json
{ "items": [] }
```

数组元素是主人视图 `Item`。

#### `GET /items/{id}`

主人看主人视图。管理员看主人视图，但仍然没有原图。其他人 `404`。

### 4.4 候选与通知（F）

#### `GET /items/{id}/matches`

只有该物品的主人。对方物品用公开投影。

响应 `200`：

```json
{
  "item_id": "uuid",
  "matches": []
}
```

没有合格候选时 `matches` 为 `[]`，不是 `404`。

#### `GET /notifications`

响应 `200`：

```json
{
  "unread_count": 1,
  "items": []
}
```

`items` 是 `Notification`，最多 100 条，新的在前。A 组的铃铛用 `unread_count`。

#### `POST /notifications/{id}/read`

无请求体。只能标自己的。响应 `200`：更新后的 `Notification`。

### 4.5 识别、找回、下架（G）

#### `GET /jobs/{id}`

只有该物品的主人。B 组每 2 秒拉一次，直到 `succeeded` 或 `failed`。

响应 `200`：`Job`。

`succeeded` 时，类别和颜色已经写在物品上，`source=model`，`confirmed=false`。B 组再 `PATCH`，并传 `confirm_tags: true`。  
`failed` 时不写标签，页面用手填。

#### `POST /claims`

失主对一条候选提交结果。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `lost_item_id` | 是 | 当前用户的 `open` 失物 |
| `found_item_id` | 是 | 一条仍 `open` 的拾获 |
| `result` | 是 | `returned` 或 `not_found` |
| `request_id` | 是 | |

响应 `201`：`Claim`。

同一对重复提交 `not_found`，返回第一次的记录。拾获已被别人标成 `returned` 时返回 `409`，`found_already_returned`。

#### `GET /claims/mine`

响应 `200`：`{ "items": [] }`，元素是 `Claim`。

#### `POST /reports`

任意登录用户。

| 字段 | 必填 |
| --- | --- |
| `item_id` | 是 |
| `reason` | 是 |
| `request_id` | 是 |

响应 `201`：`Report`。不能举报自己的物品，返回 `422`。

#### `GET /admin/reports`

仅管理员。响应 `200`：`{ "items": [] }`，默认只给 `status=open`。

#### `POST /admin/items/{id}/takedown`

仅管理员。会话里的角色必须是 `admin`。

| 字段 | 必填 |
| --- | --- |
| `version` | 是 |
| `request_id` | 是 |
| `reason` | 是 | 1–200 字，写入该物品相关举报的关闭原因 |

响应 `200`：`Item`，`status=closed`。相关 `open` 举报变为 `closed`。给物品主人一条 `item_taken_down`。

## 5. 两条例子

失物草稿：

```json
{
  "type": "lost",
  "category": "earphones",
  "color": "black",
  "occurred_on": "2026-09-28",
  "day_part": "afternoon",
  "visited_places": ["library", "teaching_a", "canteen_1"],
  "places_ordered": true,
  "subscribe_matches": true,
  "request_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7"
}
```

拾获要分三步，不能把原图和字段一次塞进创建接口：

1. `POST /files` 上传涂黑后的图，拿到 `image_id`。
2. `POST /items`，`type=found`，带上 `image_id`、`found_place`、`place_note`。
3. `POST /items/{id}/publish`。若返回了 `job_id`，轮询 `GET /jobs/{id}`，再 `PATCH` 确认类别和颜色。
