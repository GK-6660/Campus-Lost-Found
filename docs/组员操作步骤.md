# 组员操作步骤

按顺序做。命令可以整行复制。把例子里的名字换成你自己的。

仓库地址：`https://github.com/GK-6660/Campus-Lost-Found.git`

组长要先在 GitHub 上把你加进这个仓库。没加进去的话，后面推送会被拒绝。

Windows 请打开 **Git Bash**（安装 Git 时会附带）。Mac 打开 **终端**。下面的命令两边一样。

---

## 1. 第一次：装工具

每台电脑只做一次。

### 1.1 安装 Git

Mac 一般已经有。在终端输入：

```bash
git --version
```

如果提示找不到命令，再安装：

```bash
brew install git
```

Windows 打开 https://git-scm.com/download/win 下载并安装。安装时一路下一步即可。装完关掉窗口，重新打开 Git Bash，再运行 `git --version`。

### 1.2 告诉 Git 你是谁

只做一次。名字和邮箱用你自己的，邮箱要和 GitHub 账号一致。

```bash
git config --global user.name "Xiaolin"
git config --global user.email "you@example.com"
```

看一下有没有写上：

```bash
git config --global user.name
git config --global user.email
```

### 1.3 安装 uv 和 Node.js 22

后端用 uv，前端用 Node.js。不要用 pip、conda、yarn、pnpm。

Mac：

```bash
brew install uv
brew install node@22
```

没有 Homebrew 时，uv 用：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Node.js 22 从 https://nodejs.org 下载 LTS 版本。

Windows 用 PowerShell 安装 uv：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Node.js 同样从 https://nodejs.org 下载 22 LTS。装完重新打开 Git Bash。

检查：

```bash
uv --version
node --version
npm --version
```

`node` 应显示 `v22` 开头。`uv` 能打出版本号即可。

数据库和 Docker 现在不要装。

## 2. 拉取仓库

选一个放代码的文件夹。例如 Mac 的「文稿」，Windows 的「文档」。不要放在桌面上一堆压缩包里面，也不要放进另一个已经有 `.git` 的文件夹。

```bash
cd ~
mkdir -p code
cd code
git clone https://github.com/GK-6660/Campus-Lost-Found.git
cd Campus-Lost-Found
```

`git clone` 会把整个仓库下载到一个叫 `Campus-Lost-Found` 的文件夹。以后每次开工都要先进入这个文件夹：

```bash
cd ~/code/Campus-Lost-Found
```

Windows 如果家目录不同，先用资源管理器进入你放代码的地方，在空白处右键 **Open Git Bash here**，再执行 `git clone ...`。

看一下是不是在主分支上：

```bash
git status
```

第一行应是 `On branch main`。后面如果写 `working tree clean`，说明你还没有改文件，这是对的。

---

## 3. 安装项目依赖

还是在 `Campus-Lost-Found` 文件夹里。

后端：

```bash
cd backend
uv sync
```

这会按锁好的版本安装 Python 3.12 和后端需要的包。第一次会下载，需要等一会儿。

前端：

```bash
cd ../frontend
npm ci
```

`npm ci` 会按锁好的版本安装 React 和 Ant Design。不要改成 `npm install` 去装最新版。

回到仓库根目录：

```bash
cd ..
```

检查是否装好：

```bash
cd backend
uv run ruff check app
uv run python -c "import fastapi, sqlalchemy, psycopg, pwdlib; print('backend ok')"
cd ../frontend
npm run format:check
npm run typecheck
cd ..
```

四条都没有报错就可以开始。如果某条报错，把完整文字发给组长，不要自己换一种安装方式。

## 4. 分支是什么

`main` 是大家共用的、能接着用的版本。不要在 `main` 上直接改代码。

你要做一件事时，从最新的 `main` 拉出一条自己的分支。做完后用 Pull Request 合回去，然后删掉这条分支。

一个人做登录，另一个人同时做表单，互不等待。各开各的分支。

分支名用「组-事情」，全小写，中间用短横线。例如：

| 你是谁 | 分支名例子 |
| --- | --- |
| A | `group-a/login` |
| B | `group-b/lost-form` |
| C | `group-c/matches` |
| D | `group-d/admin` |
| E | `group-e/auth` |
| F | `group-f/score` |
| G | `group-g/claims` |

一件事一条分支。不要用自己的姓名当分支名，也不要一条分支用一整个学期。

## 5. 每次开工

打开终端，进入仓库：

```bash
cd ~/code/Campus-Lost-Found
```

先拿到别人已经合并的最新代码：

```bash
git switch main
git pull
```

`git pull` 是从 GitHub 下载最新的 `main`。这一步不要省略。

然后为今天这件事开一条新分支。把名字换成你的：

```bash
git switch -c group-b/lost-form
```

`-c` 的意思是新建。这条命令之后，你的修改都在这条分支上，不会直接改到 `main`。

如果这条分支昨天已经建过，不要再 `-c`。直接切回去：

```bash
git switch group-b/lost-form
```

确认当前分支：

```bash
git status
```

第一行应是 `On branch group-b/lost-form`，而不是 `On branch main`。

---

## 6. 改完之后提交

先看自己改了哪些文件：

```bash
git status
```

红色或 `modified` 是改过的文件。确认没有 `.env`、`.venv`、`node_modules`。这三样不能提交。

只加入你这次改过的文件。例子：

```bash
git add frontend/src/api/items.ts
```

改了多个文件，就多写几行 `git add`。不要用 `git add .`，以免把不该交的文件带上。

再看一眼：

```bash
git status
```

准备提交的文件会变成绿色，或写着 `Changes to be committed`。

写下这次做了什么。句子用中文或英文都可以，要让别人看懂：

```bash
git commit -m "登记页可以提交失物表单"
```

如果提示要你填写姓名邮箱，回到第 1.2 步做完再重新 `git commit`。

推到 GitHub。这条分支第一次推送用：

```bash
git push -u origin HEAD
```

以后同一条分支再推，只要：

```bash
git push
```

第一次推送时，窗口会让你登录 GitHub。用你自己的账号。登录成功后命令才会结束。

---

## 7. 开 Pull Request

推送成功后，用浏览器打开：

https://github.com/GK-6660/Campus-Lost-Found

如果页面上方有黄色提示 **Compare & pull request**，点它。

没有的话：

1. 点 **Pull requests**
2. 点绿色的 **New pull request**
3. 左边选 `main`，右边选你的分支，例如 `group-b/lost-form`
4. 点 **Create pull request**

标题写做了什么，例如「失物登记表单」。

正文写四行：

```text
组别：B
改了什么：失物登记表单可以填写并提交
怎么测的：用假数据填完表，缺字段时有提示
请谁看：同组另一人
```

改到接口、字段或全组共用的说明时，请组长也看。

点 **Create pull request**。先不要合并。

组员的 Pull Request 必须有另一个人批准，才能进 `main`。看的人打开这条 Pull Request，点 **Files changed** 看完改动，再点绿色的 **Review changes**，选 **Approve**，然后 **Submit review**。只在下面留言不算批准。写代码的组员不能批准自己的 Pull Request。

组长自己的 Pull Request 不用等别人批准。组长打开后直接点 **Squash and merge**，再点 **Confirm squash and merge**。

组员的 Pull Request 在别人批准之后，也只有组长能合并。组长点 **Squash and merge**，再点 **Confirm squash and merge**。GitHub 会删掉这条远程分支。如果下面还出现 **Delete branch**，再点一次。其他同学看到合并按钮是灰的，这是正常的，不要换成自己的账号去点。

---

## 8. 合并之后

回到终端：

```bash
cd ~/code/Campus-Lost-Found
git switch main
git pull
git branch -d group-b/lost-form
```

最后一行是删掉你电脑上的那条分支。名字换成你自己的。如果提示还没合并、删不掉，不要加 `-D`。先问组长。

下一件事情从第 5 步重新来：更新 `main`，再开一条新分支。

---

## 9. 分支做了几天，main 上已经有别人的代码

先保存并推送你自己的：

```bash
git status
git add 你改过的文件
git commit -m "这次做到哪一步"
git push
```

再把最新的 `main` 合进你的分支：

```bash
git switch main
git pull
git switch group-b/lost-form
git merge main
```

如果顺利结束，再推一次：

```bash
git push
```

如果出现 `CONFLICT`：

1. 不要继续改，不要执行 `git push --force`
2. 运行 `git status`，把列出的文件名发给组长
3. 等组长告诉你保留哪一边

---

## 10. 不要做的事

- 不要在 `main` 上改代码。`git status` 第一行如果是 `On branch main`，先开分支再改。直接 `git push origin main` 会被 GitHub 拒绝，这是正常的。
- 已经在 `main` 上改了、但还没 `commit`：立刻开分支，改动会跟着走。

```bash
git switch -c group-b/lost-form
```

- 已经在 `main` 上 `commit` 了：停下来发给组长，不要自己用 `reset`。
- 不要使用 `git push --force`。
- 不要把 `.env`、`.venv`、`node_modules` 提交上去。
- 不要自己 `pip install`、`conda install`、`npm install 某个包的最新版`。要加新包先问组长。
- 不要把没合并的分支部署到服务器。

---

## 11. 每天可以照抄的最短流程

已经克隆过、依赖也装过之后，每天就是：

```bash
cd ~/code/Campus-Lost-Found
git switch main
git pull
git switch -c group-b/lost-form
```

改代码。然后：

```bash
git status
git add 你改过的文件
git commit -m "说明这次做了什么"
git push -u origin HEAD
```

再到 GitHub 网页开 Pull Request。分支已经推送过时，最后一行改成 `git push`。
