## 1. 引言

### 1.1 目的

规定本系统的模块边界、数据、接口和公开函数，使十人可以并行实现而不会各自发明字段或调用方向。

### 1.2 范围

本系统是一个校园网站。失主登记丢失信息，拾到者上传涂黑后的照片，系统按规则给出候选和理由。失主自行标记已找回或没找到。管理员只处理举报和下架。

本期必须交付一条可演示闭环：注册登录、登记、涂黑上传、规则匹配、站内信、已找回、无模型时手填。

### 1.3 读者

实现人员按第 3 节的负责人阅读对应章节。集成负责人维护本文和第 4 节列出的共用文件。

### 1.4 组员先看的文件

| 文件 | 用途 |
| --- | --- |
| `组员操作步骤.md` | 拉取仓库、开分支、提交 |
| `环境安装.md` | 安装 uv 和 Node.js |
| `工作说明.md` | 每人改哪个文件、怎么测 |

### 1.5 不实现

本期不得实现下列能力，也不得为其增加字段或函数：交接、前台保管、私密证明、管理员批准认领、`reserved` 状态、地图选点、GPS、邮件、短信、即时聊天、向量检索、消息队列、服务端推送。

模型不得填写品牌，不得生成匹配理由，不得把分数写成归属概率。界面文案必须使用「匹配分 n/100，仅用于排序」。

## 2. 设计约束

| 编号 | 约束 |
| --- | --- |
| CON-01 | 单仓。前端 React + TypeScript，后端 FastAPI。全站一套前端框架。 |
| CON-02 | 前缀 `/api/v1`。除文件上传外，请求和响应为 JSON。响应中的空值必须写 `null`，不得省略键。 |
| CON-03 | 鉴权使用名为 `clf_session` 的 HTTP-only Cookie，`SameSite=Lax`，`Path=/`。值是会话标识，不得是用户 `id`。前端请求必须带 `credentials: "include"`。不得把令牌写入 localStorage。 |
| CON-04 | 权限只认服务端会话。请求体中的 `role` 必须忽略。 |
| CON-05 | 写操作必须带客户端生成的 `request_id`。同一用户的同一 `request_id` 再次提交时，必须返回第一次的结果，不得再次写入。注册和登录尚无用户 `id` 时，幂等范围使用 `student_no`。 |
| CON-06 | 更新物品必须带 `version`。与库中不一致时返回 `409`，并给出 `current_version`。 |
| CON-07 | 只有 `items.py` 可以修改 `items.status` 和 `items.version`。 |
| CON-08 | 只保存浏览器中已经涂黑的图片。不得保存原图，不得把原图发给模型。允许的类型为 JPEG、PNG、WebP，最大 5MB，必须校验文件头。 |
| CON-09 | 日期为 `YYYY-MM-DD`。时刻为 UTC，例如 `2026-09-29T10:00:00Z`。标识为字符串 UUID。 |
| CON-10 | 类别、颜色不在词表内时必须记为 `unknown`，不得自造字符串。 |
| CON-11 | 无模型密钥或识别超时时，系统必须仍能手填、发布、匹配和标记找回。 |
| CON-12 | 路由只做三件事：读取会话、检查幂等、调用一个服务函数。不得在路由中打分、修改状态或插入通知。 |

## 4. 依赖规则

允许的调用方向如下。箭头表示「可以调用」。

```text
claims   → items、match、notify
reports  → auth、items、notify
items    → files、tags、match、extract
extract  → files、tags
match    → scoring、notify
```

附加规则：

| 编号 | 规则 |
| --- | --- |
| DEP-01 | `match.py` 可以调用 `items.to_public_view`。不得调用 `create_item` 或 `update_item`。 |
| DEP-02 | `extract.py` 不得调用 `match.py`。 |
| DEP-03 | `scoring.py` 不得调用其他业务模块，不得访问数据库。 |
| DEP-04 | `files.py` 不得引用 `match.py`。读取权限在本模块内查询。 |
| DEP-05 | 前端除 `redact.ts` 外，业务文件必须通过 `client.request` 发请求，不得各自实现 `fetch`。 |
| DEP-06 | `schemas.py`、`errors.py`、`types.ts`、`main.py` 可以被引用。业务组不得直接修改。 |

### 5.2 枚举

`category`：`earphones` 耳机，`campus_card` 校园卡，`keys` 钥匙，`bottle` 水杯，`book` 书，`clothing` 衣物，`electronics` 电子产品，`umbrella` 伞，`bag` 包，`other` 其他，`unknown` 未知。

`color`：`black` 黑，`white` 白，`gray` 灰，`red` 红，`orange` 橙，`yellow` 黄，`green` 绿，`blue` 蓝，`purple` 紫，`pink` 粉，`brown` 棕，`multi` 多色，`unknown` 未知。打分时 `black` 与 `gray` 为同一组。

地点代码：`library` 图书馆，`teaching_a` 教学楼 A，`teaching_b` 教学楼 B，`canteen_1` 一食堂，`canteen_2` 二食堂，`dorm` 宿舍区，`gym` 体育馆，`admin_building` 行政楼。接口不得接收经纬度或 GPS。

### 5.7 分数 Score 与理由 Reason

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `score` | integer | 总分，只用于排序 |
| `score_max` | integer | 必须为 100 |
| `reasons` | Reason[] | 分项理由 |
| `reasons[].code` | enum | 见 5.2 |
| `reasons[].points` | integer | 该项得分 |
| `reasons[].text` | string | 由打分模块生成的说明，不得由模型生成 |
| `conflicts` | Reason[] | 硬冲突。没有时必须为 `[]` |
| `hard_conflict` | boolean | 类别明确不同时为真。为真时不得发站内信 |
| `notify` | boolean | 是否满足通知条件 |

分项满分：类别 40，颜色 20，地点 15，时间 15，品牌 5，关键词 5。类别明确不同记 −30。未知不加分。品牌必须双方都有且相同才计分。展示阈值 `score >= 40`，最多 5 条。通知阈值 `score >= 60`，且 `hard_conflict` 为假，且失物 `subscribe_matches` 为真。缺照片不把总分扣成 0。

过滤：类型相反，状态为 `open`，不是自己登记的记录。

时间只比较日期，时段本期不参与计算。相差天数取绝对值：

```text
S_time = 15 × max(0, 1 − Δt / 7)
```

同一天为 15，相差不少于 7 天为 0。拾获日期早于丢失日期时，理由写「时间顺序存疑」，该项再乘 0.5。实现只用这个线性公式。

地点用楼栋中心点，坐标放在 `deploy/locations.json`。拾获点为 F，失主去过的楼为 P1…Pn。`places_ordered` 为真且不少于两栋时，距离取 F 到各楼、以及 F 到每段路线的最小值；否则只取到各楼的最小值。

```text
S_place = 15 × max(0, 1 − d / 800)
```

d 的单位是米。F 就在某一栋上，理由写「出现在你去过的一食堂」。靠近路线但不是停靠点，理由写沿途距离。d 不少于 800 时地点分为 0，不因此否掉整条候选。坐标缺失时，F 在失主选过的楼里记满分，否则记 0。

理由由打分函数按模板写，例如「类别相同：耳机」。不得由模型生成。界面写「匹配分 72/100，仅用于排序」。

### 5.9 找回 Claim

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 系统生成 | 记录标识 |
| `lost_item_id` | string | 必须属于当前用户且为 `open` | 失物 |
| `found_item_id` | string | 必须为 `open` | 拾获 |
| `result` | enum | 必填 | `returned` 或 `not_found` |
| `created_at` | string | 系统写入 | 提交时刻 |

`returned` 必须把两条物品都变为 `returned`，关闭他人对该拾获的候选，并通知那些人。同一拾获只允许一条 `returned`。`not_found` 不得改变两条物品的 `open` 状态。

| `id` | string | 系统生成 | 举报标识 |
| `item_id` | string | 必填 | 被举报物品 |
| `reason` | string | 1–200 | 理由 |
| `created_at` | string | 系统写入 | 举报时刻 |
| `status` | enum | 新建为 `open` | 下架后必须变为 `closed` |

### 5.13 涂黑输入

这些字段只存在于浏览器，不得上传。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file` | File | 用户选择的原图。导出后必须丢弃 |
| `strokes` | array | 遮挡矩形 |
| `strokes[].x` | number | 左上角横坐标，单位为原图像素 |
| `strokes[].y` | number | 左上角纵坐标，单位为原图像素 |
| `strokes[].width` | number | 宽度，原图像素 |
| `strokes[].height` | number | 高度，原图像素 |

屏幕上的显示坐标必须先换算为原图像素，再导出。

### 5.14 错误体

```json
{
  "error": {
    "code": "version_conflict",
    "message": "物品已被更新，请刷新",
    "current_version": 4
  }
}
```

| `error.code` | HTTP | 何时使用 |
| --- | --- | --- |
| `unauthenticated` | 401 | 未登录 |
| `forbidden` | 403 | 已登录但不是主人或管理员 |
| `not_found` | 404 | 记录不存在，或当前用户不应知道它存在 |
| `version_conflict` | 409 | `version` 过期。必须包含 `current_version` |
| `found_already_returned` | 409 | 该拾获已有一条 `returned` |
| `invalid_state` | 409 | 当前状态不允许该操作 |
| `validation_error` | 422 | 字段不合法。必须包含 `fields` |

`fields[]` 的 `name` 是字段名，`code` 只能是 `required`、`unknown_enum`、`too_long`、`invalid_file`。各组不得另造错误 JSON。

## 6. 接口规范

未列出的路径不得实现。除 API-AUTH-01、API-AUTH-02 外，未登录访问必须返回 401。带 `request_id` 的接口必须先查幂等，成功后再保存结果。

### 6.1 账号

#### API-AUTH-01 注册

`POST /auth/register`。无需登录。成功 201，并写入 `clf_session`。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `student_no` | 是 | 见 5.3。重复时 422，`fields[].name` 为 `student_no` |
| `nickname` | 是 | 见 5.3 |
| `password` | 是 | 见 5.3 |
| `request_id` | 是 | 见 5.1。幂等键使用 `student_no` |

响应为 User，不得含 `password`。`role` 必须为 `user`。

#### API-AUTH-02 登录

`POST /auth/login`。成功 200，并写入 `clf_session`。学号或密码错误时 401，不得指出哪一项错误。

请求字段：`student_no`、`password`、`request_id`，均必填。响应为 User。

#### API-AUTH-03 退出

`POST /auth/logout`。无请求体。成功 204，并删除 `clf_session`。

#### API-AUTH-04 当前用户

`GET /auth/me`。无请求体。响应为 User。

### 6.2 文件

#### API-FILE-01 上传

`POST /files`。`multipart/form-data`。成功 201。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 见 5.4 |
| `request_id` | 是 | 见 5.1 |

响应为 StoredFile。类型或大小不合法时 422，`fields[].code` 为 `invalid_file`。

#### API-FILE-02 读取

`GET /files/{file_id}`。响应为图片字节，`Content-Type` 为保存的 `mime`。允许的读者：上传者、在自己的候选中看到该图的失主、管理员。其他人必须返回 404。

### 6.3 物品

#### API-ITEM-01 创建草稿

`POST /items`。成功 201。不得打分，不得发通知。

请求字段即 5.5 中可由客户端提交的 Item 字段，另加必填的 `type` 和 `request_id`。`expires_on`、`status`、`version`、`job_id`、`tags` 不得由客户端指定。响应为主人视图，`status=draft`，`version=1`。失物未传 `subscribe_matches` 时必须为 true。手填的类别和颜色必须写成 `source=user` 且 `confirmed=true`。

#### API-ITEM-02 修改

`PATCH /items/{item_id}`。成功 200。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `version` | 是 | 见 5.1 |
| `request_id` | 是 | 见 5.1 |
| `confirm_tags` | 否 | 见 5.5。为真时确认标签并触发匹配 |
| 其余 Item 可写字段 | 否 | 见 5.5。至少修改一项 |

只有主人可以调用。草稿，或拾获标签尚未确认时，可以修改类别、颜色、品牌、描述、地点、日期和时段。已经 `open` 且标签已确认后，只允许修改 `subscribe_matches`。成功后 `version` 加 1。

#### API-ITEM-03 发布

`POST /items/{item_id}/publish`。成功 200。请求只有 `version` 和 `request_id`。

失物必须已有 `occurred_on`、`day_part` 和至少一个 `visited_places`。拾获必须已有 `occurred_on`、`day_part` 和 `found_place`。成功后 `status=open`，`expires_on` 为 `occurred_on` 加 30 天。

后置条件：

| 条件 | 动作 |
| --- | --- |
| 失物 | 立即与现有开放拾获匹配 |
| 拾获且类别、颜色均已确认 | 立即与现有开放失物匹配 |
| 拾获有图且类别或颜色未确认 | 创建识别任务，响应含 `job_id`。此时不得匹配 |

#### API-ITEM-04 撤回

`POST /items/{item_id}/close`。成功 200。请求只有 `version` 和 `request_id`。只有主人，且当前状态必须为 `open`。成功后 `status=closed`，此后不得再匹配或通知。

#### API-ITEM-05 我的列表

`GET /items`。查询参数 `type`、`status` 均可省略。只返回当前用户的物品，最多 100 条，按 `updated_at` 降序。响应为 `{ "items": Item[] }`。

#### API-ITEM-06 详情

`GET /items/{item_id}`。主人或管理员得到主人视图。其他人 404。管理员同样不得获得原图。

### 6.4 候选与通知

#### API-MATCH-01 候选

`GET /items/{item_id}/matches`。只有主人。响应：

| 字段 | 说明 |
| --- | --- |
| `item_id` | 路径中的物品 |
| `matches` | Match 数组。`score >= 40`，最多 5 条。没有时必须为 `[]`，不得返回 404 |

对方物品必须是 PublicItem。

#### API-NTF-01 通知列表

`GET /notifications`。无请求体。响应含 `unread_count` 和 `items`，见 5.10。

#### API-NTF-02 标已读

`POST /notifications/{notification_id}/read`。无请求体，因此不做 `request_id` 幂等。只能修改自己的通知。成功 200，`read` 为 true。

### 6.5 识别、找回、举报

#### API-JOB-01 识别进度

`GET /jobs/{job_id}`。只有该物品的主人。响应为 Job。

#### API-CLM-01 提交结果

`POST /claims`。成功 201。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `lost_item_id` | 是 | 见 5.9 |
| `found_item_id` | 是 | 见 5.9 |
| `result` | 是 | `returned` 或 `not_found` |
| `request_id` | 是 | 见 5.1 |

`returned` 的后置条件见 5.9，并且必须在同一数据库事务中完成。拾获已被别人标为 `returned` 时返回 `found_already_returned`。同一对重复提交 `not_found` 时返回第一次的记录。

#### API-CLM-02 我的找回记录

`GET /claims/mine`。响应 `{ "items": Claim[] }`。

#### API-RPT-01 举报

`POST /reports`。成功 201。请求 `item_id`、`reason`、`request_id`。不得举报自己的物品，否则 422。新建记录的 `status` 为 `open`。

#### API-RPT-02 待处理举报

`GET /admin/reports`。会话角色必须为 `admin`。默认只返回 `status=open`。响应 `{ "items": Report[] }`。

#### API-RPT-03 下架

`POST /admin/items/{item_id}/takedown`。会话角色必须为 `admin`。成功 200。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `version` | 是 | 见 5.1 |
| `request_id` | 是 | 见 5.1 |
| `reason` | 是 | 1–200。写入相关举报的关闭说明 |

后置条件：物品 `status=closed`；该物品上 `open` 的举报变为 `closed`；给物品主人一条 `item_taken_down`。

## 8. 处理流程

### 8.1 发布失物

`publish_item` 锁定并开放该物品，调用 `rematch_for_lost`。匹配模块打分、写入候选，并在达到通知阈值时写一条站内信。

### 8.2 发布尚未确认标签的拾获

`publish_item` 锁定并开放该物品，调用 `enqueue`。识别只写未确认标签。本流程不得调用匹配。

### 8.3 确认标签

`update_item` 锁定物品，确认标签，调用 `on_tags_confirmed`。物品已经开放时，按类型重跑匹配。若发布前类别和颜色已经确认，则在 `publish_item` 中直接 `rematch_for_found`，不得再创建识别任务。

### 8.4 已找回

`submit_claim(result=returned)` 在同一事务中锁定失物和拾获，两条都改为 `returned`，抑制该拾获的其他候选，并通知其他人。`not_found` 只新增记录。

### 8.5 下架

`takedown` 校验管理员，锁定物品，改为 `closed`，关闭相关举报，通知主人。

页面路径由 A、B、C、D 在本地手测：登录、失物表单、涂黑上传、候选理由、已找回、举报下架。本地通过后再由集成负责人部署 `main`。个人分支不得直接部署到服务器。

## 10. 配置与部署

本地开发必须能够完成第 1.2 节的闭环。生产部署使用已有域名和 HTTPS，由 Docker Compose 运行前端、后端和 PostgreSQL。数据库迁移使用 Alembic。模型密钥和会话密钥不得提交到仓库。楼栋坐标放在 `deploy/locations.json`，只供打分使用，不向用户采集 GPS。
